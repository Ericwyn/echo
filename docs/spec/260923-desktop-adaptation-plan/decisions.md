## P2 当前采纳的桌面导航约定

- 手机继续由 `StatefulShellRoute` 管理各主 Tab 的独立栈；桌面宽屏使用独立 Navigator。两种策略只分开导航编排，页面、provider 与播放核心继续复用。
- 桌面音乐流是固定根页面。侧栏选择主目的地会替换当前主页面；页面内容打开的歌手、专辑、歌单等详情则在统一桌面 Navigator 入栈。
- 桌面返回逐层关闭详情，再回到当前主目的地，最后到音乐流；音乐流根页面不触发 Android 后台行为。重复点击当前侧栏目的地回到其主页面，不增加一层。
- 这组约定来自本轮路由讨论。返回/前进和顶部工具栏已首轮实现；`27913d3f` 让前进重建复用 route-local PageStorageBucket，滚动位置有回归用例但未运行；`859745a6` 恢复搜索页草稿与提交值；`eaa77d13` 恢复专辑/歌单排序；其他页面局部状态和 Ubuntu 实机手感仍需验证。
- Linux 桌面在 GTK runner 标题栏隐藏后，由应用根部绘制覆盖登录/设置/播放等页面的窗口栏；它提供可拖动标题区和窗口控制。主应用的返回/前进/搜索工具栏留在内容 shell 内；expanded 页面标题不再显示重复返回按钮。窗口最小逻辑宽度设为 840，与 expanded 断点一致，Android 不受窗口尺寸限制。
- 2026-09-23 更新：宽屏账户/服务器身份区已完全移除，离线任务状态页不再出现在桌面侧栏；Android 窄屏抽屉暂保留其状态入口。应用导航工具栏和侧栏品牌区使用同一个高度 token，桌面播放条外层不留边距。封面动态背景默认开启，可在设置中关闭；关闭后使用当前 Echo 主题色，选择按设备持久化。

## 实施必须维持的技术约束

- T1：一份播放状态、一份有效队列、一个实际音频解码/输出引擎及其所有者；系统适配器只转发命令和状态。原生会话宿主允许独立存在，但不持有音源或产生第二路播放，见 [Windows 接入边界](research-stream-music.md)。
- T2：保留已确认的基础/实际队列顺序、entry ID、revision、随机与循环语义；视图选择不等于播放当前位置。
- T3：系统能力与窗口宽度分别判断；窗口重排、tab 切换、托盘隐藏不会重建播放器。
- T4：所有音量路径通过 `userVolume × fadeGain`，包括暂停淡出、恢复、错误处理和 Android handler 的回退路径。
- T5：媒体会话和托盘可独立降级；系统初始化失败不使本来可用的音频播放失败。
- T6：每个平台以真实证据声明支持，编译成功、单元测试和 GNOME/Windows 桌面会话测试分开记录。
