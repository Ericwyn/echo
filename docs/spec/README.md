## 目录约定

- 需求名称沿用原计划文件名，例如 `260922-play-queue-redesign/`。
- 同日新建多个独立需求时，使用 `YYMMDD-01-<名称>/`、`YYMMDD-02-<名称>/` 表示当天的创建顺序，并在索引记录依据；不虚构不同日期。已存在的单需求目录不因补文档改名。
- 新的多文档需求以 `README.md` 为入口，说明范围、状态、文档导航和后续步骤；历史需求保留原文件即可。
- 总体设计说明产品行为和共享约束；`phase-*.md` 说明可独立执行的实施步骤、依赖和完成条件。
- 决策及验收可独立为 `decisions.md`、`acceptance.md`；只在存在实际记录时创建 `evidence/`。
- 同一需求新增文档使用已有目录日期；只有新需求另建目录。
- 目录中的链接使用相对路径；从仓库首页引用使用 `docs/spec/...`。迁移时同时检查 Markdown 链接、HTML 图片路径和脚本中的路径字符串。
- 状态只按证据更新：计划、编译通过、widget 测试、真实系统验收分别记录；旧文档的历史验收结论保持其原有范围。
